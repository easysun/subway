瀏覽器檢查曾發現並修正兩項問題：

| 問題 | 修正與證據 |
| --- | --- |
| SVG 圖表標題出現 hydration 錯誤 | 將 `<title>` 的動態內容組成單一字串子節點，修正伺服器與瀏覽器處理多個文字節點造成的差異；修正後正常顯示並完成後續操作。 |

## 身份與資料保護審查

原始碼審查涵蓋身份取得、工作區 API、資料驗證、匯入／匯出、schema／migration，以及相關客戶端持久化與渲染路徑。在下述 Sites 信任邊界成立的前提下，已審查範圍內未重現 P1／P2：

- API 由伺服器取得已登入 owner ID，讀寫都以 owner 範圍的參數化查詢執行。
- 初次建立使用 owner 唯一鍵；更新以 owner 與 revision 同時比對，衝突回傳 409。
- 寫入要求精確同源 Origin 與 JSON 類型，串流讀取時執行 1 MiB 限制，再驗證 revision 與工作區內容。
- 匯入資料會重建物件、拒絕未知欄位、限制識別碼／網址／色碼與文字長度、驗證關聯，並拒絕重複識別碼與同一期的重複付款。
- 相關顯示路徑透過 React 渲染輸入文字；審查路徑未發現直接插入 HTML 的入口或對外提交匯入資料的行為。
- 當次現有原始碼憑證模式掃描沒有匹配；本機環境檔、執行時資料庫與建置產物由 `.gitignore` 排除。未檢查 Git 歷史，亦未執行依賴套件漏洞公告稽核。

**身份信任邊界：** Sites 代理必須剝除訪客自行提供的身份標頭，再注入經驗證的身份。此次原始碼審查沒有實測正式 Sites 代理。若將 Worker 直接開放於其他託管環境，必須先改用可驗證的 session／身份 adapter，不能把任意 HTTP 標頭視為登入。

## 已知限制與待完成驗證

- 所有付款結果由使用者手動記錄；不操作銀行、不執行扣款、不代繳稅款，也不會代為取消服務商訂閱。
- 沒有銀行、信用卡、email 或帳單同步。稅費日期須依使用者自己的帳單填寫；沒有內建法定到期日判斷。
- 匯率採手動預估。已付款保留當時匯率快照，或優先使用手動填入的實際 TWD 入帳金額。
- ICS 是未來 12 個月的靜態快照，不會跟隨應用程式變更；提醒交由匯入的行事曆處理。尚未實測外部行事曆對輸出內容與鬧鐘的解讀，亦沒有 email／推播背景排程。
- 個人與工作是同一帳戶中的篩選，不是多人組織或共用帳本。
- 每帳戶上限為 500 個支出項目、50 種付款方式與 3,000 筆付款紀錄；JSON API payload 上限 1 MiB。原始格式化備份可達 4 MiB，但還原資料仍須符合實際 payload 與 schema 限制。
- 審查沒有覆蓋真實跨帳戶登入、正式 Sites 存取控制、遠端 D1 行為或 production 部署設定。私有檢視站與公開 GitHub 原始碼的存取權限需分別確認。
- 正式部署已成功；服務讀取確認 `DB.workspaces` 存在，瀏覽器開啟已發佈網址可見 ChatGPT 登入保護頁。公開 GitHub 可讀性仍由發佈流程確認；`sub.ages.tw` 已登記但 DNS／SSL 驗證仍 pending。實際設定見 [部署紀錄](deployment.md)。
